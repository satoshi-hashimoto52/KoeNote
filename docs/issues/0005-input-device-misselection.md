# Issue #0005: 入力デバイスの誤選択に気付けない

- 状態: 未対応（改善提案）
- 起点コミット: `ca0997b`（デバイス選択 UI 自体は以前から存在）
- 種別: UX / 運用リスク
- 影響: 録音内容そのもの。**気付かないまま長時間の録音が無価値になる**
- 発見経緯: E-3 の不合格原因調査。実際に約 2 時間 13 分ぶんの録音で発生した

## 実際に起きたこと

2026-08-25 の受け入れ試験で、3 セッション連続して**マイクの肉声ではなく
再生音声（動画・ウェビナー）が録音されていた**。誰も気付かず、
A-1（68 分）を「実マイクによる長時間録音」として実施したつもりで完走した。

| セッション | 録音時間 | 録音された内容 |
| --- | --- | --- |
| `20260825_テスト` | 38 分 51 秒 | ウェビナー音声 |
| `20260825_テスト_02` | 26 分 20 秒 | 動画音声 |
| `20260825_20260825_テスト_03` | 68 分 00 秒 | 動画音声 |

E-3 の「終了確認文が保存されない」という不合格は、
文字起こしパイプラインの欠陥ではなく**この取り違えが原因**だった。
末尾 5 秒を切り出して再認識した結果は `transcript.txt` の末尾と完全一致しており、
パイプラインは wav にある音声を最後まで取りこぼしていなかった。

## 気付けなかった理由

1. **入力レベルメーターは再生音声でも振れる。**
   `setInputLevel`（`useLiveTranscription.ts`）は入力の RMS を表示するだけで、
   音源がマイクかループバックかを区別しない
2. **文字起こしは正常に出力され続ける。**
   動画にも音声があるため、テキストは途切れなく増え続ける
3. **デバイス名が録音中に目に入りにくい。**
   `入力: …` は画面右下のステータスバー、`入力デバイス=…` は診断ログ 1 行目にあり、
   どちらも開始時に一度確認する運用でないと見落とす
4. **このマシンには紛らわしい入力が並んでいる。**

| デバイス | 種別 | 危険性 |
| --- | --- | --- |
| MacBook Airのマイク | 実マイク（システム既定入力） | — |
| BlackHole 2ch | 仮想ループバック（Transport: Virtual） | **システム音声を録る** |
| Microsoft Teams Audio | 仮想 | 意図しない音源 |
| LCD-MQ271XD | ディスプレイ内蔵入力 | 意図しない音源 |

5. **ループバック入力は実装上サポートされている。**
   `useLiveTranscription.ts:590` に
   「BlackHole 等のループバック入力を音声強調で消さない」というコメントがあり、
   `echoCancellation` / `noiseSuppression` / `autoGainControl` をすべて `false` にしている。
   つまり誤用ではなく**想定内の使い方**であり、UI 上で区別する必要がある

## 現状わかっている前提

- `deviceId` は `getUserMedia` へ `{ exact: ... }` で渡される（`useLiveTranscription.ts:589`）。
  選択したデバイスが使えなければ録音は開始されず、黙って別デバイスへフォールバックしない。
  **録音が始まった時点で、選択したデバイスが使われていることは保証されている**
- 表示される `deviceLabel` は `track.label`（同 605 行）。
  `getUserMedia` が実際に許可したデバイス名であり、選択値ではなく実績値
- `enumerateDevices()` はマイク権限がない状態ではラベルを返さない。
  権限未付与のときドロップダウンは「マイク 1」「マイク 2」になり、**選べない**
- 保存される `deviceId` は Chromium がオリジンごとに salt したハッシュ。
  外部からデバイス名を逆引きできない。オリジンが変わると値が無効になりうる

## 改善候補

自動判定はできない。「BlackHole を選んでいるから間違い」とは断定できず、
会議音声の録音という正当な用途がある。**警告の表現に注意が必要。**

1. **録音開始時にデバイス名を明示する（最優先）**
   開始直後に `track.label` をトーストまたはバナーで数秒表示する。
   判定も警告もせず、事実だけを出す
2. **ステータスバーの `入力: …` を目立たせる**
   録音中は常時見える位置・サイズにする
3. **仮想デバイスに中立なラベルを添える**
   既知の仮想デバイス名（BlackHole / Loopback / Soundflower / Teams Audio 等）に
   「システム音声」等の注記を付ける。禁止や警告ではなく分類の提示にとどめる
4. **開始前のテスト録音**
   3〜5 秒録って波形とテキストを見せ、意図した音源か本人に確認させる。
   自動判定を避けつつ取り違えを実質的に防げる
5. **無音・過大レベルの検出は補助にとどめる**
   マイク経路で一定時間ほぼ無音なら注意を促す程度。
   レベルだけでは音源の種別は判定できない

### 警告表現で避けること

- 「間違ったデバイスです」と断定する（ループバックは正当な用途）
- モーダルで作業を止める（毎回の録音開始が煩雑になる）
- レベル値だけを根拠に音源を推定する

## 必要なテスト

- 録音開始時に `track.label` が UI に表示される
- 権限未付与でドロップダウンにラベルが出ない状態が識別でき、案内が出る
- 保存済み `deviceId` が無効になった場合（`exact` 制約で失敗）にわかる形でエラーになる
- 仮想デバイスの注記が、既知名の増減で壊れない

## 運用面の暫定対策（コード変更なし）

受け入れ試験のチェックリストへ次を追記済み。

- 試験開始前に `入力: …` と診断ログ 1 行目の `入力デバイス=` を確認する
- BlackHole 2ch / Microsoft Teams Audio を選ばない
- E-3 では冒頭と末尾に拍手を入れ、音声区間を客観的に確認できるようにする

詳細は `docs/manual-acceptance-long-transcription.md` の
「入力音声に関する重要な注記」および E-3 の再実施条件を参照。
