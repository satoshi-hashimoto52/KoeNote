# Issue #0009: ウィンドウ最小サイズの縮小とレスポンシブ強化

- 状態: 未対応
- 起点コミット: `50c36e4`
- 種別: enhancement
- 影響: `electron/main.ts` の数値と `styles.css`

## 現状の制約（調査済み）

| # | 制約 | 値 | 場所 |
| --- | --- | --- | --- |
| 1 | Electron `minWidth` | 460 px | `main.ts` |
| 2 | Electron `minHeight` | 650 px | `main.ts` |
| 3 | 初期サイズ | 960 × 900 | `main.ts` |
| 4 | コンテンツ最大幅 | `max-width: 960px` | `styles.css` |
| 5 | 入力レベルメーター | `width: 90px`（固定） | `styles.css` |
| 6 | 診断ログ | `max-height: 220px` | `styles.css` |
| 7 | モーダル | `width: min(480px, 90vw)` | `styles.css` |

既存ブレークポイント: 760px（3列→2列）/ 700px / 560px（2列→1列）/ 520px。
`min-width: 0` は主要コンテナに入っており、レスポンシブの土台はある。

## 確定要件

- 正式な最小幅は **320 px 前後を基本目標**。280 px は参考確認のみ
- Electron の `minWidth` だけでなく Renderer も対応する
- 狭幅でグリッドを 1 列へ。ボタンを縦積みまたは適切に折り返す
- 入力欄・診断ログ・状態表示を見切れさせない
- 主要操作（録音開始・停止・クリア・マイGPTを開く）を常に利用可能にする
- アプリ全体を縦スクロール可能にする
- **文字が 1 文字ずつ不自然に折り返される幅は採用しない**
- **常時横スクロールが必要な幅は採用しない**
- モーダルの操作ボタンを見切れさせない
- **0007（資料削除）後の UI を基準に調整する**

## 確認する幅

460 px / 400 px / 360 px / 320 px / 280 px の順に確認する。
320 px で実用性を維持できれば `minWidth = 320`。
難しい場合は崩れない最小値を実測で決め、理由を記録する。

`minHeight` も実測で決める。初期サイズを小さくする必要があるかも確認し、
既存の通常表示を悪化させない範囲で提案する。

## 受入条件

- 各幅でボタン・入力欄・診断ログが画面外へ出ない
- 通常幅（960 px）のレイアウトが崩れない
- 縦に収まらない場合はアプリ全体がスクロールする
