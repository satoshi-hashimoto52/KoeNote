# Issue #0009: ウィンドウ最小サイズの縮小とレスポンシブ強化

- 状態: **解決**（`minWidth: 320` / `minHeight: 480`。5 幅を実測で確認）
- 起点コミット: `50c36e4`
- 種別: enhancement
- 影響: `electron/main.ts` の数値と `styles.css`

## 現状の制約（調査済み）

| # | 制約 | 値 | 場所 |
| --- | --- | --- | --- |
| 1 | Electron `minWidth` | 460 px | `main.ts` |
| 2 | Electron `minHeight` | 650 px | `main.ts` |
| 3 | 初期サイズ | 960 × 900 | `main.ts` |
| 4 | コンテンツ最大幅 | `max-width: 960px` | `styles.css` |
| 5 | 入力レベルメーター | `width: 90px`（固定） | `styles.css` |
| 6 | 診断ログ | `max-height: 220px` | `styles.css` |
| 7 | モーダル | `width: min(480px, 90vw)` | `styles.css` |

既存ブレークポイント: 760px（3列→2列）/ 700px / 560px（2列→1列）/ 520px。
`min-width: 0` は主要コンテナに入っており、レスポンシブの土台はある。

## 確定要件

- 正式な最小幅は **320 px 前後を基本目標**。280 px は参考確認のみ
- Electron の `minWidth` だけでなく Renderer も対応する
- 狭幅でグリッドを 1 列へ。ボタンを縦積みまたは適切に折り返す
- 入力欄・診断ログ・状態表示を見切れさせない
- 主要操作（録音開始・停止・クリア・マイGPTを開く）を常に利用可能にする
- アプリ全体を縦スクロール可能にする
- **文字が 1 文字ずつ不自然に折り返される幅は採用しない**
- **常時横スクロールが必要な幅は採用しない**
- モーダルの操作ボタンを見切れさせない
- **0007（資料削除）後の UI を基準に調整する**

## 確認する幅

460 px / 400 px / 360 px / 320 px / 280 px の順に確認する。
320 px で実用性を維持できれば `minWidth = 320`。
難しい場合は崩れない最小値を実測で決め、理由を記録する。

`minHeight` も実測で決める。初期サイズを小さくする必要があるかも確認し、
既存の通常表示を悪化させない範囲で提案する。

## 受入条件

- 各幅でボタン・入力欄・診断ログが画面外へ出ない
- 通常幅（960 px）のレイアウトが崩れない
- 縦に収まらない場合はアプリ全体がスクロールする

## 実測結果（0007 の資料削除後の UI が基準）

`scripts/responsive_check.cjs` を拡張し、本番の Chromium でビルド済みページを各幅で読み込んで計測した。

| 幅 | 横スクロール | 設定行 | 主要 4 ボタン | 重なり | 画面外へ出た要素 | 1 文字折返し |
| --- | --- | --- | --- | --- | --- | --- |
| 960 px | なし | 3 列 | すべて ok | なし | なし | なし |
| 460 px | なし | 1 列 | すべて ok | なし | なし | なし |
| 400 px | なし | 1 列 | すべて ok | なし | なし | なし |
| 360 px | なし | 1 列 | すべて ok | なし | なし | なし |
| **320 px** | **なし** | **1 列** | **すべて ok** | **なし** | **なし** | **なし** |
| 280 px（参考） | なし | 1 列 | すべて ok | なし | なし | なし |

「主要 4 ボタン」は 文字起こし開始 / 停止 / クリア / マイGPTを開く。
幅 44px 以上・高さ 24px 以上・画面内に収まることを判定した。

**320 px で実用性を維持できたため `minWidth = 320` を採用。**
280 px でも破綻は観測できなかったが、要件どおり参考確認にとどめ、正式な最小値にはしない。

### 高さ

幅 320 px で高さを変えて計測した。

| 高さ | タイトルバー | content（表示/全体） | 縦スクロール | 開始ボタン |
| --- | --- | --- | --- | --- |
| 900 px | 44 | 856 / 1225 | あり | 表示 |
| 650 px | 44 | 606 / 1223 | あり | 表示 |
| 560 px | 44 | 516 / 1223 | あり | 表示 |
| **480 px** | 44 | 436 / 1221 | あり | 表示 |
| 420 px | 44 | 376 / 1221 | あり | 表示 |

`.content` が `flex: 1; overflow-y: auto` のため、どの高さでも縦スクロールで全操作に到達できる。
420 px でも破綻しないが、**余裕を見て `minHeight = 480` を採用**した。

**初期サイズ 960 × 900 は変更しない。** 通常表示を悪化させる理由がない。

## 変更

| ファイル | 内容 |
| --- | --- |
| `electron/main.ts` | `minWidth: 460 → 320` / `minHeight: 650 → 480` |
| `frontend/src/styles.css` | 狭幅ブレークポイントを 3 つ追加（420 / 380 / 340 px） |
| `scripts/responsive_check.cjs` | 計測対象の幅と項目を拡張（ボタン可用性・重なり・縦スクロール） |

追加したブレークポイント。

- **420 px 以下**: 余白を詰め、設定行を 1 列に保つ
- **380 px 以下**: 主要ボタンを**縦積み**（`flex-direction: column` + `width: 100%`）。
  入力レベルメーターの固定幅 90px を `flex: 1` へ変更
- **340 px 以下**: 余白と診断ログの文字サイズを最小構成に

ボタン文字が 1 文字ずつ折り返されないことは、既存の `button { white-space: nowrap }` で担保されている。
